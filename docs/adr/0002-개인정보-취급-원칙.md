# 0002 — 개인정보 취급 원칙

- 날짜: 2026-09-09
- 상태: 확정
- 맥락: 확장 스코프에서 고객(상담 대상 개인)의 개인식별 정보(이름·연락처 등)를 다루게 된다. 데모라도 개인정보 취급 방법론을 실제로 적용하는 것이 포트폴리오의 강점으로 판단됐고, 고객 데이터를 실제 개인정보로 취급한다는 정책이 확정됐다. 한편 영업·상담 담당자는 휴직·퇴직 등으로 교체가 잦다는 가정하에, 담당자–고객 소유 구조를 만들면 교체 시 데이터 이관·재할당 부담이 커진다.
- 결정: (1) 고객 개인식별 필드는 **envelope encryption**으로 저장한다(마스터 키 → 고객별 데이터 키 2계층). (2) 영업·상담 담당자는 고객 소유 구조 없이 시스템에 인입된 **모든 고객의 섭취 내역을 조회**할 수 있다. (3) 고객 개인정보가 노출되는 화면 접근 시 **접근 로그**(담당자·시각·고객)를 기록하고 총관리자(admin)가 확인할 수 있게 한다. (4) 제품기획·마케팅 담당자는 고객 개인정보에 **접근하지 못한다**(역할 기반 가드). (5) 목록 화면 등에서 개인정보를 마스표시하고, 수집 필드를 최소화한다.
- 근거: 개인정보 최소노출 원칙을 유지하면서 상담 담당자 교체 가정을 반영한 접근 모델. 소유 구조 대신 접근 로그로 책임성을 확보한다. envelope encryption은 필드 단위 암호화로 데모 수준 구현량이면서 방법론을 보여주는 핵심 요소다.
- 대안: (1) 담당자–고객 소유 기반 접근 제어 — 담당자 교체 시 데이터 이관 문제가 생겨 교체 가정과 충돌. (2) 암호화 없이 마스킹만 적용 — "실제 개인정보로 취급" 결정(ADR-0001 맥락)을 충족하지 못함.

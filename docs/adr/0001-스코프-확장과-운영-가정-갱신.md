# 0001 — 스코프 확장과 운영 가정 갱신

- 날짜: 2026-09-09
- 상태: 확정
- 맥락: seed.yaml 1차 스펙은 "로컬 Docker Compose 포트폴리오 데모"까지만을 목표로 하고 실제 제품 수준 보안·운영 고도화를 비목표로 했다. 이후 방향이 "건강기능식품 기업 담당자(영업·상담, 제품기획·마케팅)가 활용하는 도구"로 확장되면서, 기능·디자인·데이터 구조가 실사용 가정을 전제해야 자연스러워졌다. 그러나 실제 배포까지 목표로 하면 클라우드·성능·운영 인프라까지 스코프가 커져 포트폴리오 데모라는 프로젝트 성격과 어긋난다.
- 결정: 로컬 Docker Compose는 유지하고, **"사내 담당자가 사용한다"는 가정만 도입**해 기능·디자인·데이터 구조를 설계·구현한다. 실제 동시 사용·운영 인프라는 비목표로 유지한다. 이에 따라 seed.yaml의 운영 관련 제약이 갱신된다: "실제 제품 수준의 보안/운영 고도화는 비목표" → "개인정보 취급 방법론을 데모 수준으로 구현한다(ADR-0002)". "법령 데이터만 RAG 대상", "식약처 데이터는 구조화 조회" 제약은 그대로 유지된다. 역할 3종(총관리자, 영업·상담, 제품기획·마케팅)과 간소화 RBAC(Role 테이블 + 가드·데코레이터)을 도입한다.
- 근거: 역할 분리, 접근 로그, 개인정보 암호화 같은 기능은 "실사용 가정"이 있어야 설계가 성립하고, 포트폴리오 차별화 요소(간소화 RBAC, envelope encryption, 접근 로그)도 이 가정 위에서만 의미가 있다. 동시성 고려를 배제해 데모 단순성을 유지한다.
- 대안: (1) 데모 단순성을 유지하며 개인정보 방법론을 생략 — 포트폴리오 차별성 감소. (2) 실제 사내 배포까지 목표로 함 — 운영 인프라 스코프가 데모 목표를 초과.

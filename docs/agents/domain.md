# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 소비하는 방식.

## 탐색 전에 읽을 것

- 저장소 루트의 **`CONTEXT.md`** (용어집)
- **`docs/adr/`**: 작업하려는 영역을 다루는 ADR을 읽는다.

해당 파일이 없으면 **조용히 진행**한다. 부재를 지적하지 않고, 만들자고 먼저 제안하지도 않는다. `/domain-modeling` 스킬이 용어나 결정이 실제로 확정될 때 파일을 지연 생성한다.

ADR 본문 양식(날짜/상태/맥락/결정/근거/대안)은 `docs/obsidian-vault.md` 3절의 확정 양식을 따른다. `docs/adr/`가 원본(단일 출처)이고, Obsidian 전역 Vault의 `Decisions/`는 symlink로 연결해 참조한다.

## 파일 구조

single-context (이 저장소):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-<결정명>.md
│   └── 0002-<결정명>.md
├── backend/
└── frontend/
```

## 용어집 어휘를 사용한다

출력에서 도메인 개념을 이름 지을 때(이슈 제목, 리팩터 제안, 가설, 테스트 이름) `CONTEXT.md`의 정의대로 쓴다. 용어집이 피하라고 명시한 동의어로 흐르지 않는다.

필요한 개념이 아직 용어집에 없다면 그것도 신호다: 프로젝트가 쓰지 않는 언어를 발명하고 있는 것인지(재고려), 실제 갭인지(노트로 남겨 `/domain-modeling`에 전달) 판단하라.

## ADR 충돌을 표시한다

출력이 기존 ADR과 모숫되면 조용히 무시하지 말고 명시적으로 드러낸다:

> _ADR-0007(이벤트 소싱 주문)과 모숫되지만, 다시 열 가치가 있다. 이유는 …_
